# FlowMask 项目介绍

> 网络流量敏感数据分级脱敏与防泄漏系统
> 数据安全大赛 · 自主命题（数据脱敏 + 大模型交叉）· 2026-10-18

## 一句话介绍

FlowMask 在旁路镜像流量上做**内容级**敏感数据识别：先用毫秒级规则引擎全量扫描，再按需升级到本地 BERT 与本地大模型复核，把每条命中数据映射到 `L3 高危 / L2 中危 / L1 低危 / SAFE` 四级，输出**脱敏副本 + 分级 + 可读解释**，并在看板上完成"泄露了什么、多严重、怎么处置"的闭环——**全程本地运行，数据不出机**。

## 要解决的问题

企业业务系统会把个人信息与凭证明文放进 HTTP 报文：

```http
POST /api/order
{"name":"张三","phone":"13800138000","id_card":"11010519491231002X","address":"福建省福州市鼓楼区五四路 1 号"}
```

这类报文一旦被旁路抓取、日志采集或第三方 SDK 拿走，就是**可直接利用**的泄露。现有手段都不够好：

| 方案 | 为什么不够 |
| --- | --- |
| 纯正则 DLP | 误报高：`4111111111111111` 到底是卡号还是随机数？`13800138000` 是测试数据还是真实手机？ |
| 纯大模型识别 | 单条 2-5 秒，线上流量根本跑不动；且必须把原文送到外部服务，违反数据安全底线 |
| 一刀切封堵 | 业务不可用；低危信息（IP、示例邮箱）也被拦 |

FlowMask 的取舍是：**用规则保证吞吐，用模型保证准确，用分级决定处置**。

## 三个核心设计

### 1. 三级协同，按需升级

| 级别 | 技术 | 成本 | 触发范围 |
| --- | --- | --- | --- |
| L1 | 12 条正则 + 校验算法（身份证 MOD 11-2、银行卡 Luhn） | < 1ms | 全量流量 |
| L2 | bert-base-chinese 多标签（ONNX int8，CPU） | 5-20ms | 仅 L1 命中样本 |
| L3 | 本地 Qwen2.5-3B-Instruct（Q4，Ollama） | 2-5s | 仅 L2/L3 样本 |

绝大多数流量在 L1 就被判定为 SAFE 直接丢弃，算力只花在真正可疑的数据上。推理服务超时或不可用时降级回 L1 结果（`degraded=true`），不阻塞链路。

### 2. 可解释的四级分级

```
score = 最高加权项（类别差异化赋权 × 置信度）
      + 多标签共现修正（每类 +0.06，封顶 0.18）
      + 身份类共现加成（2 类 +0.10、≥3 类 +0.15）
身份证 / 银行卡 / 密钥凭据：一票直达 L3
阈值：≥0.85 L3 · ≥0.55 L2 · ≥0.25 L1 · 其余 SAFE
```

实测示例（`go run ./cmd/flowmask` 输出）：

| 样本 | 计算 | 级别 |
| --- | --- | --- |
| 仅手机号 | 0.65 × 0.95 = **0.6175** | L2 |
| 仅邮箱 | 0.45 × 0.90 = **0.405** | L1 |
| 邮箱 + 地址 | 0.405 + 0.06 + 0.10 = **0.565** | L2 |
| 手机 + 银行卡（CSV） | 0.828 + 0.06 = **0.888** | L3 |
| 姓名 + 手机 + 身份证 | 0.931 + 0.18 + 0.15 = **1.00**（封顶） | L3 |

### 3. 四级脱敏

| 级别 | 处置 | 示例 |
| --- | --- | --- |
| L3 | 全屏蔽 | `11010519491231002X` → `[已屏蔽:身份证号]` |
| L2 | 保留首字符 + 星号 | `13800138000` → `1******` |
| L1 | 前置警示 | `[低危]` + 原文，仅进告警供人工复核 |
| SAFE | 原文放行 | — |

只改命中片段、保留上下文语义；**数据库只存脱敏副本，原始敏感值不入库**。

## 创新点

1. **规则 + 小模型 + 大模型的成本分级**：把大模型从"全量识别器"降级为"少量样本的解释器"，让 8GB 显存的机器也能在真实流量上跑三级协同；
2. **可解释分级**：每条 finding 带命中类别、权重、共现依据与自然语言理由，评分过程可复算、可审计，不是黑盒；
3. **校验位驱动的误报抑制**：身份证 MOD 11-2、银行卡 Luhn 在正则之后做二次验证，直接排除"形状对、校验错"的号码；
4. **完全本地化闭环**：采集 → 识别 → 分级 → 脱敏 → 落库 → 看板 → 审计导出全部本地完成，镜像回环地址，不依赖任何外部服务；
5. **工程化落地而非论文原型**：复用一套已开源、可 Windows/Linux 双跑、带 Web 看板与告警的流量监控底座（采集端 0.24.1），在其上增量接入 DLP 链路。

## 与赛题需求的对应

| 赛题模块 | 实现状态 |
| --- | --- |
| 流量采集与协议解析 | ✅ 采集（pcap 回放 / Windows Npcap / Linux AF_PACKET / 合成）；🚧 TCP 重组与 HTTP/JSON/表单解析 |
| 三级协同识别 | ✅ L1 规则 + 评分；⏳ L2 BERT、L3 本地大模型 |
| 敏感度评分与四级分级 | ✅ 加权最大 + 共现修正 + 直达阈值 |
| 四级脱敏 | ✅ 四种模板，实测输出正确 |
| 告警联动 | ⏳ 分级告警 + Bearer Token 远程推送 |
| 可视化看板 | ⏳ 饼图/柱状/时间线/脱敏对照（基于既有 Vue3 客户端扩展） |
| 审计日志导出 | ✅ `dlp_findings` 落库（SQLite/JSONL）+ `/api/v1/dlp/export` JSONL 导出（含 meta 行） |

> 说明：本系统基于**旁路镜像**，不串接业务数据路径，因此"脱敏/拦截"的对象是**可审计的脱敏副本与告警动作**；在线改写仅作为可选扩展，不作为主线承诺。

## 技术栈

| 层 | 技术 |
| --- | --- |
| 采集与解析 | Go 1.25+、AF_PACKET / Npcap / pcap 回放、零拷贝载荷切片、gopacket tcpassembly（规划） |
| 识别与分级 | Go 正则 + MOD 11-2 / Luhn 校验；bert-base-chinese ONNX int8；Qwen2.5-3B-Instruct（Ollama） |
| 服务 | Go net/http（REST + SSE）、SQLite（modernc.org/sqlite，纯 Go 无 CGO）、Prometheus 指标 |
| 展示 | Vue3 + Vite + ECharts，Tauri 桌面端 |
| 推理服务 | Python 3.12 + FastAPI + ONNX Runtime（仅监听回环地址） |

## 目录结构（关键部分）

```text
cmd/
  netmon/        采集端主程序（上游，Windows/Linux 双跑 + Web 控制台）
  flowmask/      DLP 命令行：pcap → 识别 → 评分 → 脱敏 → 表格/JSON 输出
  genpcaps/      演示数据生成器：6 类场景合成 pcap（含预期级别，可直接当回归用例）
internal/
  capture/       数据源：pcap 文件 / Npcap / AF_PACKET / 合成 / 回放
  parser/        以太网 + IPv4/IPv6 + TCP/UDP 解析，Payload() 载荷定位
  dlp/           L1 规则、评分分级、四级脱敏
  flow/ storage/ aggregator/ api/ alert/ plugin/ ...
client/          Vue3 + Tauri 看板
docs/            设计文档、项目介绍、上游产品文档
```

## 快速体验（无需管理员权限）

```powershell
go run ./cmd/genpcaps                     # 生成 data/demo-dlp.pcap（6 类场景）
go run ./cmd/flowmask                     # 检测并打印：级别/五元组/类别/得分/脱敏预览
go run ./cmd/flowmask -db data/flowmask.db # 检测结果落库 SQLite，供网页接口查询
go run ./cmd/netmon -source replay -replay-file data/demo-dlp.pcap -offline
                                          # 用采集端回放，浏览器打开看板
# 让采集端读同一份库（[storage] sqlite_path = "data/flowmask.db"）后：
curl.exe "http://127.0.0.1:8080/api/v1/dlp/stats?since=3600&step=300"
```

## 与上游项目的关系

本作品基于团队自研并已开源的「Linux 网络流量监控系统」（采集端 0.24.1）二次开发：复用其采集、解析、聚合、存储、API、Web 看板与告警框架，新增载荷定位、DLP 识别评分脱敏、演示数据生成与 DLP 命令行等能力。上游项目定位为**流量运维监控**，本作品在其上补足**内容级数据安全**能力，二者共享同一套 Go 主干与前端。
