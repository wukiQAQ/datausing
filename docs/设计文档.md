## 1. 背景与目标

### 1.1 要解决的问题

业务系统大量把个人信息与凭证放进 HTTP 报文（下单中的姓名/手机/身份证、注册表单中的邮箱/地址、上传接口中的银行卡 CSV、接口 URL 中的 `api_key`）。这些内容一旦被旁路抓包、日志采集或第三方 SDK 拿到，就是完整的、可直接利用的泄露。

传统方案两难：

| 方案 | 问题 |
| --- | --- |
| 纯正则/关键字 DLP | 误报高（`4111111111111111` 卡号 VS 普通长数字），无法判断上下文语义 |
| 纯大模型识别 | 2-5 秒/条的延迟，`2k` 上下文跑不动线上流量；且必须把原文送到外部服务，违反"数据不出机" |
| 一刀切封堵 | 业务不可用；低危信息（IP、普通邮箱）也被拦 |

### 1.2 我们的目标

在**旁路镜像流量**上做**内容级**识别，按敏感度分四级处置，且全链路本地化：

1. **准**：规则 + 语义模型 + 大模型三级协同，L1 负责召回、L2/L3 负责降误报与解释；
2. **快**：绝大多数流量停在 L1（<1ms），只有命中样本才升级，整体 P95 < 50ms；
3. **省**：只把 L2/L3 样本送本地大模型，8GB 显存即可跑（Qwen2.5-3B Q4）；
4. **可审计**：每条 finding 落库，原始敏感值不入库，只存脱敏副本与命中原因。

### 1.3 与赛题需求的对应

| 赛题功能模块 | 本设计中的实现 | 章节 |
| --- | --- | --- |
| ① 流量采集与协议解析（HTTP/JSON/CSV/文本） | `internal/capture` 采集 + `internal/parser` 载荷定位 + 后续 TCP 重组/HTTP 解析 | 第 3、4 章 |
| ② 三级协同敏感识别 | L1 规则（`internal/dlp/rules.go`）+ L2 BERT + L3 本地 LLM | 第 5 章 |
| ③ 敏感度评分与四级分级 | 加权最大 + 共现修正 + 极端阈值直达 → `L3/L2/L1/SAFE` | 第 6 章 |
| ④ 四级脱敏 | 全屏蔽 / 保留首字符+星号 / 前置警示 / 原文 | 第 7 章 |
| ⑤ 告警联动（脱敏/拦截/放行） | findings → 告警事件 → Bearer Token 推送 | 第 9 章 |
| ⑥ 可视化看板 | Vue3 + ECharts：分级分布、类别 TopN、时间线、脱敏对照 | 第 9 章 |
| ⑦ 审计日志导出 | `dlp_findings` 表 + JSONL 审计导出 | 第 8 章 |

> **口径说明（重要）**：本系统基于**旁路镜像**，不串接在数据路径上，因此"脱敏/拦截"的对象是**可审计的脱敏副本与告警动作**，而不是改写业务流量。在线改写仅作为可选扩展（反向代理演示），不作为主线承诺。

## 2. 总体架构

### 2.1 分层

```text
┌───────────────────────────── 展示层 ─────────────────────────────┐
│ Vue3 + ECharts 看板（Tauri 桌面端 / 浏览器）：分级分布、类别 TopN、   │
│ 时间线、finding 列表、脱敏前后高亮对照、审计导出                    │
└───────────────────────────────▲──────────────────────────────────┘
                                │ REST + SSE
┌───────────────────────────── 服务层（Go）─────────────────────────┐
│ internal/api：现有流量 API + 新增 /api/v1/dlp/*                    │
│ internal/storage：SQLite（metrics / flows / dlp_findings）/ JSONL  │
│ internal/alert：阈值告警 + 远程推送                                │
└───────────────────────────────▲──────────────────────────────────┘
                                │ findings
┌───────────────────────────── 识别层 ─────────────────────────────┐
│ internal/dlp：L1 规则识别 → 评分分级 → 脱敏模板                     │
│ （可选）inference/：Python 微服务，提供 L2 BERT / L3 LLM 复核       │
└───────────────────────────────▲──────────────────────────────────┘
                                │ 有界队列（丢帧计数）
┌───────────────────────────── 采集解析层（Go）────────────────────┐
│ internal/capture：pcap 文件 / Windows Npcap / Linux AF_PACKET /     │
│                   synthetic 合成                                    │
│ internal/parser：以太网/IPv4/IPv6/TCP/UDP 解码 + Payload 载荷定位   │
└──────────────────────────────────────────────────────────────────┘
```

### 2.2 数据流（旁路异步）

```text
抓包 goroutine（不阻塞）
   └─> Packet{Raw}
        ├─> 现有链路：parser.Parse → flow.Table → aggregator → storage → 流量指标 API
        └─> DLP 链路：parser.Payload → 有界队列 → N 个识别 worker
                          └─> L1 规则 → 未命中则丢弃（绝大多数流量在此结束）
                                 └─> 命中 → 评分分级 → 脱敏副本
                                        ├─> L2 BERT（批量 ≤32，超时 2s）
                                        └─> L3 LLM（仅 L2/L3 样本，超时 5s，失败降级）
                                                 └─> finding → SQLite + SSE + 告警
```

关键设计：

- **不进主链路**：DLP 在独立 worker 中执行，采集侧只做一次载荷切片投递，队列满则丢帧并累加 `dlp_dropped` 指标（不静默丢）；
- **分级升级**：L1 是召回层（快、宽），L2 是精排层（语义、多标签），L3 是解释层（只给结论与理由）；
- **失败可降级**：推理服务不可用/超时 → 回落到 L1-only 结果，并在 finding 上标记 `degraded=true`。

### 2.3 线程与背压

| 组件 | 并发模型 | 背压策略 |
| --- | --- | --- |
| 采集 | 1..8 个 reader（可 PACKET_FANOUT） | 内核环形缓冲 + 丢包计数 |
| DLP 队列 | 有界 channel（默认 4096） | 满则丢弃最旧帧，`dlp_dropped++` |
| 识别 worker | 默认 4 | 单条载荷上限 64KB，超长截断并标记 |
| 推理调用 | 每 worker 同步 HTTP | 超时 + 熔断（连续失败 5 次降级 30s） |

## 3. 采集与解析

### 3.1 数据源（复用基线）

| 数据源 | 用途 | 说明 |
| --- | --- | --- |
| pcap 回放 | 演示、回归测试、离线分析 | `-source replay -replay-file x.pcap` |
| Windows Npcap | 本机实时抓包 | 需管理员权限，`live_windows.go` |
| Linux AF_PACKET | 服务器实时抓包 | 生产形态，支持 fanout / CPU 绑定 / 内核过滤下推 |
| synthetic | 无权限环境的演示 | 随机载荷，**不含真实 HTTP**，故另有 `genpcaps` |

### 3.2 载荷定位（新增 `internal/parser/payload.go`）

基线解析器只输出 `Info.L4Payload`（长度），拿不到内容。新增：

```go
func PayloadSpan(frame []byte) (start, end int, ok bool) // 载荷在帧内的字节区间
func Payload(frame []byte) ([]byte, bool)                // 载荷切片（零拷贝视图）
```

处理细节：

- 以太网头 14B，支持 802.1Q/QinQ 双层 VLAN；
- IPv4：按 `total length` 截断，剔除以太网最小帧填充（`len(frame)` 常大于真实 IP 长度）；
- IPv6：跳过 ≤4 个扩展头（逐跳/路由/分片/AH/目的选项），再定位 L4；
- TCP：按 `data offset` 跳过选项（含时间戳、SACK 等），L4 头长度可变；
- UDP：固定 8B；
- 边界：分片报文（`frag offset > 0`）不产出载荷，交由上层重组或丢弃。

### 3.3 协议还原（进行中）

- **TCP 重组**：采用 `github.com/google/gopacket/tcpassembly`（成熟、纯 Go），按五元组与序列号还原双向流；
- **应用层解析**：先识别 HTTP/1.x（请求行/头/`Content-Length`/`chunked`），再按 `Content-Type` 分派 JSON / `x-www-form-urlencoded` / CSV / `text/plain`；
- **降级**：非 HTTP 流量直接对载荷文本跑 L1（覆盖裸 TCP 明文协议、UDP 载荷）。

## 5. 识别层设计（三级协同）

### 5.1 分工与成本

| 级别 | 技术 | 单条成本 | 职责 | 触发条件 |
| --- | --- | --- | --- | --- |
| L1 | 正则 + 校验算法（MOD 11-2 / Luhn）+ 键值字段 | < 1ms（纯 Go，无 IO） | 高召回，识别结构化与半结构化敏感串 | 全量流量 |
| L2 | bert-base-chinese 多标签分类（ONNX int8，CPU） | 5-20ms | 语义判定：这段文本是否真的在处理敏感信息、有哪些类别 | 仅 L1 命中的样本 |
| L3 | 本地 LLM（Qwen2.5-3B-Instruct Q4_K_M，Ollama） | 2-5s | 给出级别复核与**可读解释**（判定依据） | 仅 L2/L3 样本，限流+超时 |

### 5.2 L1 规则表（已实现，`internal/dlp/rules.go`）

| 规则 | 类别 | 正则要点 | 权重 | 置信度 | 校验 |
| --- | --- | --- | --- | --- | --- |
| `idcard18` | 身份证号 | 6 位地址码 + 出生日期 + 顺序码 + 校验位 | 0.95 | 0.98 | MOD 11-2 |
| `idcard15` | 身份证号 | 15 位旧格式 | 0.80 | 0.70 | — |
| `mobile` | 手机号 | `1[3-9]\d{9}` 词边界 | 0.65 | 0.95 | — |
| `bankcard` | 银行卡号 | `62/4/5[1-5]` 开头 13-17 位 | 0.90 | 0.92 | Luhn |
| `email` | 邮箱 | 常规邮箱 | 0.45 | 0.90 | — |
| `ipv4` | IP 地址 | 四段点分 | 0.15 | 0.80 | 段值 ≤255 |
| `secret_kv` | 密钥凭据 | `api_key=/password:/token:` 键值 | 1.00 | 0.95 | — |
| `jwt` | 密钥凭据 | `eyJ...` 三段式 | 1.00 | 0.97 | — |
| `pem_private_key` | 密钥凭据 | `-----BEGIN PRIVATE KEY-----` | 1.00 | 0.99 | — |
| `name_kv` | 姓名 | `姓名/name: "..."` | 0.40 | 0.75 | — |
| `address_kv` | 地址 | `地址/address: "..."` | 0.50 | 0.75 | — |
| `medical_kv` | 医疗信息 | `病历/诊断/疾病:` 等 | 0.75 | 0.80 | — |

工程细节：

- **校验位剔除误报**：18 位身份证按 MOD 11-2 验算、银行卡按 Luhn 验算，形状对但校验错的直接不命中；
- **去重叠**：命中按下标排序后去掉重叠区间，保证同一段文本不会被重复计分（也保证脱敏不会二次替换）；
- **键值型只取值**：`"password": "a1b2"` 只把 `a1b2` 当敏感内容，键名不参与脱敏；
- **兼容中英文标点**：支持 `:` / `：`、`=`、引号包裹等写法。

### 5.3 L2：BERT 多标签（规划）

- 模型：`google-bert/bert-base-chinese`（110M）→ ONNX 导出 + 动态 int8 量化，CPU 推理约 150MB / 5-20ms；
- 输入：还原后的文本窗口（≤128 token，取命中位置附近窗口，避免超长）；
- 输出：多标签概率（`id_card/phone/bank_card/email/secret/name/address/medical/benign`）+ 置信度；
- 训练数据：规则命中的样本自动标注 + 人工抽检修正 + 公开数据集（中文个人信息脱敏语料）混合，目标 F1 ≥ 0.85；
- 作用：把"看起来像但语境无害"的样本（测试数据、文档示例）降级，减少误报。

### 5.4 L3：本地大模型复核（规划）

- 模型：`qwen2.5:3b-instruct-q4_K_M`（约 2.0GB，2K 上下文占用约 3.5GB，35-60 tok/s）；
- 输入：脱敏后的文本片段 + L1/L2 的结构化结果（**不送原文敏感值**）；
- 输出：严格 JSON `{"level":"L3","reason":"命中的身份证号可唯一定位到自然人，且与手机号共现"}`；
- 约束：单条超时 5s、并发 1-2、结果按内容哈希缓存（相同片段不重复推理）、连续失败熔断降级；
- 兜底：`qwen2.5:1.5b` 或纯 L1 结果（`degraded=true`）。

### 5.5 Go ↔ Python 契约

```http
POST /v1/classify
Content-Type: application/json

{
  "items": [
    {
      "id": "pkt-1024",
      "content": "…脱敏后的文本…",
      "content_type": "json",
      "l1_hits": [{"type": "id_card", "value_len": 18, "count": 1}]
    }
  ]
}
```

```json
{
  "results": [
    {
      "id": "pkt-1024",
      "l2": [{"type": "id_card", "score": 0.96}, {"type": "phone", "score": 0.91}],
      "l3": {"level": "L3", "reason": "身份证号与手机号共现，可唯一定位到自然人", "model": "qwen2.5:3b-instruct-q4_K_M"},
      "latency_ms": 4210,
      "degraded": false
    }
  ]
}
```

- 批量 ≤ 32 条；L2 超时 2s，L3 超时 5s；Go 侧超时即回退 L1 结果；
- 服务只监听 `127.0.0.1:8090`，不对外暴露。

## 6. 评分与分级模型（已实现，`internal/dlp/score.go`）

### 6.1 算法

```
score = max(weight_i × confidence_i)                        # ① 类别差异化赋权取加权最大
      + min(0.06 × (类别数-1), 0.18)                        # ② 通用共现修正（封顶 0.18）
      + (身份类字段数≥3 ? 0.15 : 身份类字段数==2 ? 0.10 : 0)  # ③ 身份类共现加成
      ，上限 1.0

if 命中类别 ∈ {身份证, 银行卡, 密钥凭据}:  level = L3       # ④ 极端阈值直达
else:                                     level = 阈值映射(score)
```

阈值映射：`≥0.85 → L3`、`≥0.55 → L2`、`≥0.25 → L1`、其余 `SAFE`。

### 6.2 为什么这样设计

- **取最大而不是求和**：一段文本里出现 5 个 IP 仍然是低危，不应因为"数量多"升级；
- **共现修正有上限**：多类别共现才意味着"能组合定位到自然人"，但要防止类别一多就分数爆表；
- **身份类单独加成**：姓名/手机/地址/邮箱/身份证之间任意两类同时出现，就构成可关联身份，所以额外 +0.10；
- **极端阈值直达**：证件号、银行卡、密钥是三张"一票高危"牌，不受加权影响，避免被低权重类别拉低。

### 6.3 计算示例（与实测输出一致）

| 样本 | 最高加权项 | 共现修正 | 结果 | 级别 |
| --- | --- | --- | --- | --- |
| 仅手机号 | 手机 0.6175 | 无 | 0.6175 | L2 |
| 仅邮箱 | 邮箱 0.405 | 无 | 0.405 | L1 |
| 仅 IPv4 | IP 0.12 | 无 | 0.12 | SAFE |
| 表单（邮箱+地址） | 邮箱 0.405 | 0.06 + 0.10 | 0.565 | L2 |
| CSV（手机+银行卡） | 银行卡 0.828 | 0.06 | 0.888 | L3（且直达） |
| JSON（姓名+手机+身份证） | 身份证 0.931 | 0.12 + 0.15 → 封顶 | 1.00 | L3（且直达） |

## 7. 四级脱敏（已实现，`internal/dlp/mask.go`）

| 级别 | 模板 | 示例（原文 → 脱敏后） |
| --- | --- | --- |
| L3 高危 | 全屏蔽 | `11010519491231002X` → `[已屏蔽:身份证号]` |
| L2 中危 | 保留首字符 + 星号 | `13800138000` → `1******`、`zhang.san@example.com` → `z******` |
| L1 低危 | 前置警示 | `[低危]` + 原文（仅在告警记录中出现，用于提示复核） |
| SAFE | 原文 | 不做处理 |

原则：

- **只改命中片段**，不改上下文——保留上下文才能让评审/运营看懂"这条数据是在什么业务里泄露的"；
- **脱敏结果可展示、原文不入库**：`dlp_findings.masked` 存脱敏副本，原始敏感值只在内存中短暂存在；
- **类别用中文名**：模板里写 `[已屏蔽:身份证号]` 而不是 `[MASKED]`，演示与报告更直观。

### 8.2 新增 `dlp_findings`（**已实现**）

```sql
CREATE TABLE IF NOT EXISTS dlp_findings (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  ts           INTEGER NOT NULL,          -- 秒级时间戳（与 flows 表口径一致，便于 join）
  src_ip       TEXT    NOT NULL,
  src_port     INTEGER NOT NULL,
  dst_ip       TEXT    NOT NULL,
  dst_port     INTEGER NOT NULL,
  proto        TEXT    NOT NULL,          -- tcp / udp
  host         TEXT,                      -- HTTP Host（可空）
  path         TEXT,                      -- 请求路径（可空）
  content_type TEXT,                      -- json / form / csv / text
  level        TEXT    NOT NULL,          -- L3 / L2 / L1
  score        REAL    NOT NULL,
  types        TEXT    NOT NULL,          -- 逗号分隔：id_card,phone
  hits         INTEGER NOT NULL,
  masked       TEXT    NOT NULL,          -- 脱敏后的载荷片段（不含原文）
  reasons      TEXT,                      -- L2/L3 解释，JSON 数组
  model        TEXT,                      -- l1 / bert / qwen2.5-3b
  payload_bytes INTEGER NOT NULL,
  degraded     INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_dlp_ts        ON dlp_findings(ts);
CREATE INDEX IF NOT EXISTS idx_dlp_level_ts  ON dlp_findings(level, ts);
CREATE INDEX IF NOT EXISTS idx_dlp_src       ON dlp_findings(src_ip);
CREATE INDEX IF NOT EXISTS idx_dlp_types     ON dlp_findings(types);
```

保留策略：默认 7 天（`findingRetention`），与 `flows` 的 24h 分别配置；审计导出走 JSONL（一行一条 finding + 导出时间戳与操作人）。

> **实现状态**：SQLite（`internal/storage/finding_sqlite.go`）与 JSONL（`finding_file.go`）双后端均已落地，
> 统一走 `storage.FindingStore` 接口（Append/Finding/QueryFindings/ExportFindings/FindingStats），
> 采集端启动时用类型断言挂到 API 上；CLI 可用 `go run ./cmd/flowmask -db data/flowmask.db` 直接写入同一张表，
> 因此初赛演示可以「先离线跑一遍 → 网页/接口立刻能查」。

## 10. 性能目标与评测方案

### 10.1 指标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| L1 单条耗时 | < 1ms | 纯 Go，无 IO |
| L1+L2 端到端 P95 | < 50ms | 含队列等待与批量推理 |
| 三级（含 L3）端到端 | 2-5s | 仅 L2/L3 样本，可接受 |
| 回放吞吐 | ≥ 5k pkt/s | 单机 8 核 |
| 识别 F1 | ≥ 0.85 | 自建标注集 |
| 分级准确率 | ≥ 0.85 | 四级混淆矩阵 |
| 误报率 | ≤ 10% | SAFE 样本被判为 L1 及以上 |
| 内存 | < 300MB（不含模型） | Go 进程 RSS |
| 显存 | < 6GB | L2 int8 + L3 Q4_K_M 峰值 |

### 10.2 数据集

- **合成集**：`cmd/genpcaps` 的 6 个场景（JSON/表单/CSV/明文/带密钥/对照），规模可参数化扩到数千条，用于回归与吞吐测试；
- **半真实集**：在授权环境采集的 HTTP 明文流量（去标识化后入库）；
- **标注集**：人工标注 300-500 条（每类 ≥ 30），用于计算 F1 与分级准确率；
- **否定集**：测试数据、示例文档、随机数字串（考验校验位剔除与 L2 语义）。

### 10.3 基准命令

```powershell
go test ./... -count=1                                  # 功能回归
go test ./internal/dlp/ -bench=. -benchmem              # L1 规则吞吐
go run ./cmd/flowmask -pcap data/demo-dlp.pcap -quiet   # 端到端耗时（stats.duration_ms）
```

## 11. 安全与合规

| 风险 | 应对 |
| --- | --- |
| 原始敏感数据泄露（日志/库） | 只存脱敏副本；`masked` 字段不含原文；调试日志默认不打印载荷 |
| 把数据送到外部模型 | 模型全部本地部署（Ollama + ONNX），推理服务只监听回环地址 |
| 抓包越权 | 只读镜像口/本机回环；文档明确"需授权环境"，提供 pcap 回放模式做无权限演示 |
| API 越权 | 支持 Bearer Token；`/api/*` 统一鉴权（SSE 支持 query token）；监听地址默认回环 |
| 误报导致业务误判 | 分级处置而非阻断；L2/L3 双复核；finding 带解释与置信度，支持人工复核 |
| 模型供应链 | 权重来自 ModelScope 官方仓库，校验 sha256；不引入需联网的第三方依赖 |

合规口径：本作品在自有设备、自有数据与合成数据上演示，不采集他人流量。
