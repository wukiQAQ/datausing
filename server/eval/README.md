# 评测集与跑分（自建标注集）

本目录是 FlowMask 的**自建评测集**：`dataset.jsonl` 一行一个样本，用来量化
「识别 → 评分 → 分级」这条链路的效果，指标由 `python -m app.evaluate` 自动生成到
[`docs/评测报告.md`](../../docs/评测报告.md)。

```powershell
cd server
python -m app.evaluate                       # 默认只跑 L1，几秒钟出结果
python -m app.evaluate --enable-l2           # 接入 L2 推理服务后对比增益
python -m app.evaluate --enable-l2 --enable-l3
```

## 样本格式

| 字段 | 说明 |
| --- | --- |
| `id` | 样本编号，形如 `L3-001`（前缀是标注级别，便于人工核对） |
| `format` | `text` / `json` / `csv` / `sql`，评测时走对应解析器 |
| `content` | 样本原文（JSON/CSV/SQL 是完整的待解析文本） |
| `level` | 人工标注的期望级别：`L3` / `L2` / `L1` / `SAFE` |
| `types` | 期望命中的类别（英文键，如 `id_card`、`phone`） |
| `note` | 这条样本想验证什么（判错时一眼能看懂原因） |

## 标注口径（重要，报告里也如实写明）

1. **标签按需求 v2 的分级策略人工标注**，不是"跑一遍程序再把输出当标准答案"：
   - L3：证件（身份证/银行卡/密钥凭据）等一票高危，或高分共现组合；
   - L2：手机号、多字段共现（手机+邮箱、姓名+地址+邮箱等）、医疗健康字段；
   - L1：单一低权重字段（仅邮箱、仅姓名、仅地址）；
   - SAFE：无敏感内容，或"形态像但校验不通过"的干扰项。
2. **类别只标 L1 能依据形态判定的**：姓名/地址需要字段名上下文（`姓名:`、`address:`）才算命中；
   没有字段名的裸姓名属于 L2 语义识别职责，不在本集里标成 L1 命中。
3. **困难样本照实计入失分**：带连字符/空格的号码、全角数字、base64 编码、碰巧通过 Luhn 的订单号等，
   故意保留在集合里——它们就是要暴露的问题，修掉之后指标才会上来（项目里也因此补了
   "归一化"和"银行卡 BIN 校验"）。
4. 数据集是自己造的，**不代表公开语料上的绝对水平**；它的价值在于"同一把尺子量迭代"，
   以及给答辩提供可复算、可解释的数字。

## 当前结果（L1 only，67 条，2026-10-19）

| 指标 | 数值 |
| --- | ---: |
| 分级准确率 | 98.5% |
| 分级 Macro-F1 | 0.987 |
| 类别 Micro-F1 | 0.993 |
| 高危漏检率 | 0.0% |
| 安全误报率 | 0.0% |
| L1 单条时延 | p50 0.03 ms / p95 0.11 ms |

唯一一条级别判错：base64 编码的联系方式（`L2-018`）——L1 不解析编码，属于 L2/L3 或解码插件的职责，
已在报告「已知局限」里写清楚。

## 扩充建议

- 继续加真实格式变体：带国家码的手机号、护照/统一社会信用代码、多语言地址；
- 加**语义型**样本（含姓名但无字段名的自然语句）并开启 L2，量化"多模型协同"的增益；
- 目标规模 300~500 条后，再按类别统计支持数，避免小样本下 P/R 抖动误导结论。
