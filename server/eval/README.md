# 评测集与跑分（自建标注集）

本目录是 FlowMask 的**自建评测集**：`dataset.jsonl` 一行一个样本，用来量化
「识别 → 评分 → 分级」这条链路的效果，指标由 `python -m app.evaluate` 自动生成到
[`docs/评测报告.md`](../../docs/评测报告.md)。

```powershell
cd server
python -m app.evaluate                       # 默认只跑 L1，几秒钟出结果
python -m app.evaluate --enable-l2           # 接入 L2 推理服务后对比增益
python -m app.evaluate --enable-l2 --enable-l3
```

## 样本格式

| 字段 | 说明 |
| --- | --- |
| `id` | 样本编号，形如 `L3-001`（前缀是标注级别，便于人工核对） |
| `format` | `text` / `json` / `csv` / `sql`，评测时走对应解析器 |
| `content` | 样本原文（JSON/CSV/SQL 是完整的待解析文本） |
| `level` | 人工标注的期望级别：`L3` / `L2` / `L1` / `SAFE` |
| `types` | 期望命中的类别（英文键，如 `id_card`、`phone`） |
| `note` | 这条样本想验证什么（判错时一眼能看懂原因） |

## 标注口径（重要，报告里也如实写明）

1. **标签按需求 v2 的分级策略人工标注**，不是"跑一遍程序再把输出当标准答案"：
   - L3：证件（身份证/银行卡/密钥凭据）等一票高危，或高分共现组合；
   - L2：手机号、多字段共现（手机+邮箱、姓名+地址+邮箱等）、医疗健康字段；
   - L1：单一低权重字段（仅邮箱、仅姓名、仅地址）；
   - SAFE：无敏感内容，或"形态像但校验不通过"的干扰项。
2. **类别只标 L1 能依据形态判定的**：姓名/地址需要字段名上下文（`姓名:`、`address:`）才算命中；
   没有字段名的裸姓名属于 L2 语义识别职责，不在本集里标成 L1 命中。
3. **困难样本照实计入失分**：带连字符/空格的号码、全角数字、base64 编码、碰巧通过 Luhn 的订单号等，
   故意保留在集合里——它们就是要暴露的问题，修掉之后指标才会上来（项目里也因此补了
   "归一化"和"银行卡 BIN 校验"）。
4. 数据集是自己造的，**不代表公开语料上的绝对水平**；它的价值在于"同一把尺子量迭代"，
   以及给答辩提供可复算、可解释的数字。

## 与训练数据隔离（重要）

评测集是**考卷**，不能当练习册：

- `python -m l2_training dataset` 默认**只生成自举数据**，不读 `eval/dataset.jsonl`；
  早期版本默认用 `--with-eval` 并入，导致训练集包含评测样本，指标虚高（已修）。
- 阈值（`benign≥0.65` / 直达类 `≥0.75`）是在这 75 条留出集上调出来的，调参与评测同集，
  报告中会注明"阈值消融"性质；真实泛化能力以新增样本为准。
- 改动 `eval/dataset.jsonl` 后要重跑 `python -m app.evaluate`，报告会随代码一起提交。

## 关于「文档/测试示例」样本（BENIGN-*）

真实业务里，接口文档、测试数据、演示脚本中经常出现形似的号码（`13800138000`、示例身份证号）。
它们**不需要脱敏**（本来就是公开样例），但纯规则一定会被形状骗到——这 8 条标注 SAFE 的样本
就是用来量化「L2 语义复核能压掉多少误报」的，属于有意的困难负样本，不是标错。

## 数据集构成（2026-10-20）

主集 `dataset.jsonl` **165 条** = 策展 75 条 + 程序生成 90 条，由 `python eval/build_dataset.py` 可复现重建：

| 维度 | 分布 |
| --- | --- |
| 分级 | L3 50 / L2 44 / L1 26 / SAFE 45 |
| 格式 | text 124 / json 18 / sql 12 / csv 11 |
| 类别 | phone 48 / name 41 / address 27 / id_card 23 / email 24 / secret 18 / bank_card 10 / medical 8 / ip 4 |

- 生成样本固定种子（`seed=2026`），重跑结果一致；id 由 `_dedupe_ids` 保证唯一（策展与生成撞号时自动顺延）；
- **与训练集 0 重叠**（`data/l2_training.jsonl` 存在时逐条做内容哈希比对，报告里也会打印）；
- 每条样本的标注级别都用评分口径反算校验过，`tests/test_eval_dataset.py` 会守住这些约束。

压力集 `ner_stress.jsonl` **40 条**：来自公开语料 `weibo_ner/dev` 的自由文本句子（人名/地名），
把实体嵌进「张三昨天从福州赶过来…」这类**没有字段名**的叙述里——L1 规则抓不到、只能靠 NER，
金标一律 L1、类型只含 `name`/`address`。噪声词（亲属称谓、职业、网络用语）已用黑名单 + 姓氏启发式过滤。

## 当前结果（2026-10-20，165 条主集 + 40 条压力集）

主集三档（L2 = 8091 ONNX int8 真模型，L3 = 8092 指令裁判真模型）：

| 指标 | L1 only | L1 + L2（真模型） | L1 + L2 + L3 |
| --- | ---: | ---: | ---: |
| 分级准确率 | 92.1% | **99.4%** | **99.4%** |
| 分级 Macro-F1 | 0.926 | 0.994 | 0.994 |
| 类别 Micro-F1 | 0.880 | 0.880 | 0.880 |
| 高危漏检率 | 0.0% | 0.0% | 0.0% |
| 安全误报率 | 26.7% | **0.0%** | **0.0%** |
| L1 单条时延 | p95 0.09 ms | 含一次 L2 HTTP 调用 | 含 L3 复核（灰区样本） |

- 唯一剩下的分级错误 1 条：base64 编码的联系方式（L1 不解析编码，属 L2/L3 或解码插件职责）；
- L3 在 165 条上**不改变分级**（默认「只升不降 + 封顶 L2」），只贡献解释与证据；
- NER 开关（`--enable-ner`，需 `models/bert4ner`）：主集准确率仍 99.4%、类别 Micro-F1 **0.880 → 0.940**
  （召回 0.847 → 0.995，多 25 个 FP 类别）、p95 78.8 → 193.2 ms；**压力集从 0.0% / 0.000 提升到 90.0% / 0.952**、p95 29.6 ms。

复现命令：

```powershell
cd server
python eval/build_dataset.py                     # 重建主集 + 压力集（可复现）
python -m app.evaluate --compare-l2 --compare-l3 `
  --l2-endpoint http://127.0.0.1:8091/v1/classify `
  --l3-endpoint http://127.0.0.1:8092/v1/judge    # 主集三档对比 → docs/评测报告.md
$env:FLOWMASK_ENABLE_NER="1"; $env:FLOWMASK_NER_MODEL_DIR="models/bert4ner"
python -m app.evaluate --dataset eval/ner_stress.jsonl --enable-ner   # 压力集
```

## 扩充建议

- 继续加真实格式变体：带国家码的手机号、护照/统一社会信用代码、多语言地址；
- 主集群已达到"每级 ≥20 条"的下限，下一目标 300 条，按类别统计支持数后再下结论；
- 压力集可以扩到 200 条并加入更多噪声类型（口语、错误标注），用来说明 NER 的边界；
- 若要评估真实泛化能力，需要与训练分布无关的第三方语料，本集只用于"同一把尺子量迭代"。
